## 3. 개별 아이디어

### A. 3D 기어 공방 `gears/`
- **콘셉트** — 판의 슬롯에 톱니바퀴를 꽂고 손잡이를 돌리면 맞물린 톱니가 함께 돈다.
- **플레이 흐름** — 손잡이 톱니 드래그 → 맞물린 톱니 회전 → "풍차가 초당 2바퀴" 미션이 초록으로 바뀜 → 다음 미션.
- **재미 요소** — "내 톱니바퀴가 저 톱니바퀴를 굴린다"가 실시간으로 보인다. 마블린 머신 감성.
- **배우는 것** — 기어비(톱니 수 역비), 곱셈, 비, 회전 방향 반전.
- **새 검증 축** — 회전 동역학 + 링크비 전파 + 톱니 기하(반지름 ∝ 톱니 수).
- **판정 수치** — 출력 각속도 == 입력 × (N₁/N₂) ±1e-9 · 인접 기어 중심거리 == r₁+r₂ ±1e-6 ·
  회전 방향 부호 반전 · 2단 기어비는 곱 · 비정상 조합(같은 톱니 수 반복) 탐지.
- **재사용 자산** — 톱니바퀴 메시 생성기와 기어비 계산 → 시계·바퀴 달린 트럭·깃발·물레방아.
- **리스크** — 톱니 형상(ExtrudeGeometry) 정합. 슬롯 스냅으로 배치 오차를 없앤다.

### B. 3D 물감칠 공방 `paint/`
- **콘셉트** — 로봇/우주선 표면을 색칠해 그림을 완성한다.
- **플레이 흐름** — 색 고르기 → 표면 클릭해 칠하기 → 영역 단위 칠하기 → 목표 그림과 비교 → 점수.
- **재미 요소** — 초등 1·2학년 최애 활동. 칠한 색이 즉시 보여야 기가 죽지 않는다.
- **배우는 것** — 색 분류, 영역 구분, 공간지각.
- **새 검증 축** — 표면 셀 그래프 + 국소 flood fill + 정점별 색상 비교 채점.
- **판정 수치** — 표면 샘플 2000점 중 목표 색 일치율 ≥95% · 경계 영역 분리 정확도 · 과잉 칠 면적 0.
- **재사용 자산** — 색 팔레트 UI + 표면 셀 분할 + 국소 색칠 → 도형 조작실 색칠 모드, 분자 원자 색, 동물 우리 색칠.
- **리스크** — 표면을 규칙적 셀로 쪼갤 구조 설계가 필요.

### C. 3D 빛 거울 공방 `laser/`
- **콘셉트** — 거울을 돌려 레이저를 목표에 맞춘다.
- **플레이 흐름** — 레이저 발사 → 거울에 튕겨 순서대로 통과 → 목표 구체 명중 → 다음 퍼즐.
- **재미 요소** — "아 저렇게 하면 되는데!" 하는 발견 쾌감.
- **배우는 것** — 반사 법칙, 각도, 인과 추리.
- **새 검증 축** — 기하 광학(평면 반사 벡터), 광선 스텝.
- **판정 수치** — 반사 방향 == 반사 법칙 ±1e-9 · 목표 도달 여부 · 반사 횟수 · 광선 예산 초과 시 안전 종료.
- **재사용 자산** — 광선 반사 계산 → 탄도 궤적 시각화, 카메라 레이.
- **리스크** — 미러 회전 조작 UX(15° 스냅), 발광 렌더 비용.

### D. 3D 주사위 놀이 `dice/`
- **콘셉트** — 주사위를 굴려 말을 옮기고 숫자 미니게임으로 넘어간다.
- **플레이 흐름** — 주사위 굴리기(3D 낙하) → 숫자만큼 말 이동 → 색깔/더하기 맞히기 → 다음 턴.
- **재미 요소** — 주사위는 게임의 시작. 친구와 번갈아 하면 더 재밌다.
- **배우는 것** — 확률, 기댓값, 덧셈.
- **새 검증 축** — 시드 난수 결정론 + 자세→면 매핑 + 턴 상태 머신.
- **판정 수치** — 같은 시드 → 동일 결과열(100회) · 면 값 == 면 법선 방향 · 기댓값 3.5 ±0.15.
- **재사용 자산** — 보드 칸·토큰 경로·주사위 → 사다리타기, 체스, 숫자 덧셈 보드 등 한 엔진으로 여러 게임.
- **리스크** — 낮음. 굴림은 감쇠 진동 연출이면 충분.

### E. 3D 균형저울 `balance/`
- **콘셉트** — 양팔에 무게물을 올려 시소매를 맞춘다.
- **플레이 흐름** — 추 선택 → 팔에 올리기 → 기울어짐 → 위치 조절 → 수평이면 잠금 → 3판 승부.
- **재미 요소** — 시소매는 실패 자체가 웃긴다.
- **배우는 것** — 무게중심, 모멘트, 나눗셈(초6 역학).
- **새 검증 축** — 역학 평형(토크) + 무게중심.
- **판정 수치** — Σ토크 == 0 ±1e-9 · 빔 기울기 == atan2(Στ, Σmg) · 무게중심이 두 지지점 사이.
- **재사용 자산** — 토크 계산 → 외상·구조물 게임.
- **리스크** — 낮음. 판정이 가장 명확하지만 깊이가 얕다.

### F. 3D 구름 점프 `cloud/`
- **콘셉트** — 구름 발판을 점프해 넘는다.
- **플레이 흐름** — 좌우 이동 + 점프 → 발판 밟고 점수 → 떨어지면 리스타트.
- **재미 요소** — 순수 아케이드. 가장 "재미"하지만 규칙이 게임을 덮는다.
- **배우는 것** — 거의 없음(반응속도).
- **새 검증 축** — 캐릭터 컨트롤러 + 스윕(CCD) 충돌 + 3인칭 카메라 리그.
- **판정 수치** — 스텝 크기 무관하게 발판 관통 0 · 착지 판정 · 완주 시간.
- **재사용 자산** — 3인칭 컨트롤러 → 이후 모든 3인칭 게임.
- **리스크** — 높음. README가 이 모델의 약점으로 "카메라·정밀 인터랙션"을 지목했다.

### G. 3D 전개도 맞추기 `net/`
- **콘셉트** — 큐브 전개도를 접어 목표 도형을 만든다.
- **플레이 흐름** — 전개도 조각 회전·이동 → 접기 애니메이션 → 면 색 비교.
- **재미 요소** — 중상. 공간지각 숙련용.
- **새 검증 축** — 전개도 접힘 시 면 라벨 대응.
- **판정 수치** — 접힌 면 배치 == 정답 배치 · 면 색 일치율.
- **재사용 자산** — 면 라벨링 기반 큐브 조립 → 동물·로봇 큐브 빌더.
- **리스크** — 전개도 생성과 접힘 계산.

### H. 3D 기차 레일 `rail/`
- **콘셉트** — 선로를 연결해 기차를 목적지까지 보낸다.
- **플레이 흐름** — 스위치 조작 → 기차 출발 → 선로 분기 → 화물 싣기 → 도착지 배달.
- **재미 요소** — 기차가 달리는 소리와 연기.
- **배우는 것** — 경로 분기, 화물 개수.
- **새 검증 축** — 선로 그래프 연결성 + 경로 최적화.
- **판정 수치** — 경로 길이 == 최단 경로 · 화물 수량 보존 · 분기 상태 전이 무모순.
- **재사용 자산** — 선로/분기 노드 → 트랙 레이아웃 편집기.
- **리스크** — `maze/`의 경로 탐색 축과 겹친다.

### I. 3D 그림 그리기 `draw/`
- **콘셉트** — 3D 캔버스에 큐브를 얹어 그림을 만든다.
- **재미 요소** — 자유 표현. 채점보다 표현에 집중.
- **새 검증 축** — 자유 배치 상태의 비교 채점.
- **판정 수치** — 목표 이미지 대비 셀 일치율(기준 해법 실측값).
- **재사용 자산** — 큐브 격자 배치 도구 → 격자 조립 게임.
- **리스크** — 자유작품은 채점 기준이 애매해지기 쉽다.

## 5. 추천

**1위 A 기어 공방**
1. 재미가 별 설명 없이 성립한다 — "톱니바퀴가 맞물려 도는 것"은 규칙 설명 전에 손댈 수 있다.
2. 재사용 자산이 명확하고 넓다 — 톱니바퀴 메시 생성기는 이후 어떤 게임에도 붙는다.
3. 검증이 수치로 끝난다 — 기어비·중심거리·회전방향을 1e-9로 고정할 수 있다.

**대안** — B(재사용 자산은 가장 넓고 위험 3), D(위험 1, 벤치 축 차별성은 3으로 낮음), E(가장 빠르고 판정 명확, 재미 3).

**조합 아이디어** — 기어 + 주사위(기어로 굴리는 공이 주사위 눈을 만든다) · 물감칠 + 전개도(접어 만든 큐브를 색칠한다).

## 6. 채택한 로드맵

A → B → D 순으로 3종을 만든다. `common/parts/` 에 3D 공용 부품 계층을 두고,
첫 게임이 남긴 부품을 다음 게임이 물려받는다.

```
common/parts/            ← 3D 공용 부품 계층(신규)
  gear3d.js              톱니바퀴 메시 + 기어비        (A가 남김)
  paint3d.js             표면 셀 + 국소 색칠          (B가 남김)
  board3d.js             보드 + 토큰 + 주사위          (D가 남김)
```

- `common/parts/*.test.js` 는 vitest가 `**/*.test.js` 로 자동 수집해 회귀가 자동으로 보호된다.
- **A → B → D 순서**를 택한 이유. 첫 게임은 어련도 높은 기어(회전 기구), 둘째는 색칠(자유도·표면 규칙),
  셋째는 보드(상태 머신·상호작용) — 난이도 상승곡선이고, 뒤 게임은 앞 게임의 부품을 그대로 물려받는다.
- 각 게임의 상세 설계는 [`PLAN-gears.md`](PLAN-gears.md) · [`PLAN-paint.md`](PLAN-paint.md) ·
  [`PLAN-dice.md`](PLAN-dice.md) 에 있다.

| 3D 그림자 극장 | 광원 → 직교 투영 · 실루엣 일치 | 빛과 그림자, 투영 | 중 | `sculpt` 실루엣 IoU, `laser` 광선 |
| 3D 구조 다리 | 정적 평형 · 부재력 · 지지 조건 | 힘의 합, 구조 | 중상 | `balance` 모멘트 |
| 3D 회전 퍼즐 | 순열 · 패리티 · 회전 합성 | 공간 추론, 규칙 찾기 | 중 | `shapes` 회전, `net` 면 대응 |

**추천** — 19번째는 "3D 대칭 공방"이 가장 안전합니다. 기존 SDF·회전군 부품을 재사용하면서
"대칭 연산을 수치로 판정한다"는 새 축을 추가할 수 있습니다. 단, 새 게임을 만들기 전에
`common/engine/stage.js`와 터치·접근성 계층을 먼저 안정화하는 것이 좋습니다.
