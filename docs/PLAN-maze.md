| 게임 | 검증하는 능력 |

| `zoo/` | 절차적 지오메트리 조립 + 애니메이션 |

**이번에 새로 검증하는 능력**

1. **1인칭 카메라 리그** — 요·피치, 포인터락, 자유 시점 전환
2. **절차적 그래프 생성** — 시드 고정 DFS 완전 미로
3. **상태 공간 탐색** — (위치 × 획득 열쇠) 상태로 최단 경로 계산
4. **격자 이동 해석** — 벽 충돌과 모서리 미끄러짐
5. **부분 탐색 지도** — 방문한 칸만 그리는 미니맵

## 2. 게임 정의

**핵심 루프**: 절차 생성된 3D 미로를 1인칭으로 걸어다니며 열쇠를 모아 문을 열고 출구로 나간다.
걸은 칸 수를 **알고리즘이 구한 최적 경로**와 비교해 판정한다.

- **이동**: 방향키(또는 WASD)로 상하좌우 이동. 한 번에 한 칸. 벽에 막히면 진행 방향으로 미끄러진다
- **시점**: 마우스로 둘러본다(포인터락). `M` 키로 미로 전체를 내려다보는俯瞰 시점으로 전환한다
- **미니맵**: HUD 캔버스에 방문한 칸만 그린다
- **열쇠와 문**: 열쇠를 주우면 대응하는 문이 열린다. 문은 출구로 가는 길의 마지막 구간에 놓인다
- **판정**: 걸은 칸 수를 최적 경로와 비교해 별 3/2/1을 준다. 결과 화면에 "최적보다 N칸 더 걸었다"를 보여 준다

**par 은 손으로 정하지 않는다.** 레벨 시드의 미로에서 BFS로 계산한 최적 경로 길이를 그대로 쓴다.
항상 달성 가능한 기준이다.

## 5. 파일 구조 (모듈 7개 이내)

```
maze/
  index.html
  README.md
  src/
    maze.js       미로 생성(DFS·시드 PRNG) · 상태공간 BFS · 이동 해석 (순수, three 없음)
    levels.js     레벨 8종 데이터 + 스텝 판정·별점 (순수)
    mazeView.js   벽·바닥·열쇠·출구 메시 생성
    stage.js      렌더러·안개·손전·1인칭/俯瞰 카메라·포인터락
    invariants.js 기하 불변식
    hud.js        HTML 연결(상태·미니맵 캔버스)
    main.js       상태 머신(입력·이동·수집·판정) + UI 배선
    maze.test.js  단위 테스트
```

```js
// maze.js
generateMaze(cols, rows, seed)       // → { cols, rows, cells, start, exit, keys, gates }
shortestRoute(maze, start, exit)     // → { steps, path }  (위치 × 열쇠 상태공간 BFS)
resolveMove(cell, facing, desired, maze) // → { cell, facing, moved, slid }
reachableCount(maze)                // → 연결된 칸 수
```

**포인터락은 직접 구현한다.** 벤더에는 `OrbitControls` 만 있고, 리그(요·피치)와
자유 시점 전환을 함께 제어해야 하므로 외부 애드온에 기대지 않는다.

## 6. 검증 3층

### 1층 — 단위 테스트 (34개)

| 묶음 | 검증 내용 |
|---|---|
| 생성 | 같은 시드 → 같은 미로, 다른 시드 → 다른 미로, 모든 칸 연결, 통로 수 = 칸수-1, 경계 밖 통로 없음 |
| 최단 경로 | BFS 결과가 실제 최단(작은 미로에서 전수 비교), 잠긴 문은 막힘, 열쇠를 미리 가지면 열림 |
| 이동 | 열린 벽으로만 통과, 막힌 벽이면 미끄러짐, 모서리에서 대각 진입 불가 |
| 판정 | 스텝 구간 → 별 3/2/1, par 은 항상 달성 가능 |

### 2층 — 기하 불변식 (0.5초마다)

플레이어가 격자 칸 안 · 열쇠/출구 좌표 유한 · 벽이 격자 밖에 없음 · 시점 각도 유한 ·
최적 경로가 실제로 도달 가능

### 3층 — 화면 판정

4시점(기본·카드·정면·측면·상단) 캡처 + 콘솔 오류 0 + 개체 가시성.
자동 검사 단계는 `__gameApi.solve()`(BFS 최적 경로를 따라 실제 이동) → 출구 도달 → 결과 팝업 캡처.

## 9. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 1인칭 카메라와 4시점 자동 검사가 충돌 | 카메라를 리그(요·피치)와 분리하고, 검사 시점 지정은 리그를 덮어쓴다. 플레이 중에는 포인터락 사용 |
| 헤드리스에서 포인터락 미작동 | 자동 검사는 `__gameApi.solve()` 사용. 포인터락 실패 시에도 방향키 이동과 자유 시점은 동작한다 |
| 미로가 지루하거나 막힘 | 완전 미로 + 시드 고정 + 열쇠로 방향 부여 + BFS 최단 경로가 항상 존재 |
| 판정 공정성 | par 을 같은 BFS 알고리즘으로 계산 → 손맛 파라미터 없음 |
| 탐색 깊이 증가 | 상태 수는 (칸수 × 2^열쇠). 열쇠 5개면 32배로 제한된다 |
| 모듈 수 증가 | 모듈 7개 이내, 도메인 로직 250줄 이내 유지 |
