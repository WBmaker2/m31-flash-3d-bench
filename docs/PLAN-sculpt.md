## 1. 왜 이 게임인가 — 기존 8종과 축 분리

| 게임 | 검증하는 능력 |
|---|---|
| `zoo/` | 절차적 지오메트리 조립 + 애니메이션 |
| `molecule/` | 클릭 상호작용 + 화학 규칙 + 판정 |
| `defense/` | 실시간 상태 머신 + 경로 + 전투 |
| `shapes/` | 3D 회전 + 격자 배치 + 형상 판정 |
| `ballistics/` | 수치 적분 + 연속 충돌 + 조준 |
| `robot/` | 역기구학 + 관절 체인 + 링크 충돌 |
| `maze/` | 1인칭 카메라 + 절차 생성 + 최단 경로 탐색 |
| `flock/` | 다체 에머전트 행동 + 이웃 탐색 |

**이번에 새로 검증하는 능력**

1. **암시적 곡면(implicit surface)** — 표면을 정점 좌표가 아니라 *함수*로 정의한다.
   앞의 8종은 전부 정점을 직접 썼으므로 정반대 축이다.
2. **CSG(구성적 입체 기하)** — 합집합·교집합·차집합을 부호거리장으로 결합한다.
3. **등표면 메시 추출** — 마칭 테트라히드라로 격자에서 삼각형 메시를 만든다.
   위토폴로지(맨폴드)·방향(와인딩)·부피 보존을 숫자로 확인한다.
4. **실루엣 정량 채점** — CPU 레이캐스팅으로 목표와 자기 실루엣의 IoU를 계산한다.
5. **부피 정량 채점** — 발산정리로 메시 부피를 구해 해석해와 대조한다.

**판정이 "잘 보이면"이 아니라 숫자다.** 덕분에 "값이 맞는 것과 보이는 것이 다르다"를
이 게임에서 곧바로 측정할 수 있다.

## 2. 게임 정의

**핵심 루프**: 반투명 고스트(목표 형태)를 보고 기본형(구·박스·토러스·캡슐)을 3D 공간에
놓고 **연산(합/교/차)** 을 쌓아 목표와 비슷한 형태를 만든다. HUD에 실루엣 일치도(IoU)가
실시간으로 뜨고, "채점" 버튼으로 확정한다.

- **플레이어 조작**
  - 팔레트에서 기본형 선택 → 작업대 클릭 → 그 지점에 부품 배치 (현재 연산이 새 부품에 적용)
  - 부품 클릭 → 선택 → 드래그로 이동 / `[` `]` 로 회전 / `-` `=` 로 크기 / `Delete` 로 삭제
  - 연산 전환: 합 / 교 / 차 (바닥 순서대로 쌓임)
  - `Ctrl+Z` 실행 취소 · `R` 초기화 · `G` 고스트 표시·숨김
- **판정**: 실루엣 IoU (정면·옆 2시점 평균) + 부피 오차 + 사용 부품 수
- **별점**: 별3 = iou ≥ 0.94 · 별2 = ≥ 0.88 · 별1 = ≥ 0.80
  레벨마다 붙는 **목표값**은 기준 해법의 실측 IoU 다. 항상 달성 가능하다
  (`maze/`의 par = BFS 최적 경로와 같은 원칙).
- **레벨**: 8종. 목표는 플레이어보다 **부자한 어휘**(라운드 박스·엘립soid·매끈한 합)로
  정의해 근화가 필요하다.

**점수는 카메라와 무관해야 한다.** 채점용 직교 카메라(정면·옆)를 따로 고정하고
CPU 레이캐스팅으로 계산한다. 화면을 돌려도 점수가 흔들리지 않는다.

## 4. 레벨 8종

| # | 레벨 | 목표 형태 | 기준 해법 | 허용 부품 | 목표 IoU |
|---|---|---|---|---|---|
| 01 | 첫 조각 | 구 | 구 1개 | 2 | 기준 해법 실측 |
| 02 | 두 덩어리 | 매끈한 합(구+구) | 구 2개 | 3 | 기준 해법 실측 |
| 03 | 구면 조각 | 구 − 구 | 구 − 구 | 3 | 기준 해법 실측 |
| 04 | 렌즈 | 구 ∩ 구 | 구 ∩ 구 | 3 | 기준 해법 실측 |
| 05 | 버섯 | 매끈한 합(캡슐+구) | 캡슐 + 구 | 4 | 기준 해법 실측 |
| 06 | 긴 알 | 타원체 | 캡슐 | 4 | 기준 해법 실측 |
| 07 | 각진 상자 | 라운드 박스 | 박스 | 4 | 기준 해법 실측 |
| 08 | 마지막 조각 | 매끈한 합(토러스+구) − 구 | 토러스 + 구 − 구 | 6 | 기준 해법 실측 |

기본형 4종(구·박스·토러스·캡슐)과 연산 4종(합·교·차·매끈한 합)이 모두 등장하고,
목표만 쓰는 어휘(라운드 박스·타원체)도 실제 레벨에 쓰인다.
단위 테스트가 "모든 연산과 기본형이 레벨에 등장하는가" 를 검사한다.

각 레벨은 `reference`(기준 해법 조작 리스트)를 함께 정의한다. 이 해법의 IoU를 목표값으로
삼고, 단위 테스트가 **모든 레벨에서 기준 해법이 목표 이상을 달성함**을 확인한다.

## 5. 파일 구조

```
sculpt/
  index.html
  README.md
  src/
    sdf.js        기본형·CSG·목표 어휘·레이마칭·실루엣 IoU (순수, three 없음)
    mesh.js       마칭 테트라히드라 등표면 추출 + 발산정리 부피 (순수, three 없음)
    levels.js     레벨 8종 + 기준 해법 + 채점·별점 (순수)
    sculptView.js 결과 메시 · 목표 고스트 · 부품 표시 · 선택 표시
    stage.js      렌더러·조명·작업대·카메라·고정 스텝 루프
    invariants.js 기하 불변식
    hud.js        HTML 연결
    controls.js   포인터·키보드 입력 해석 (상태는 main.js 가 들고 있다)
    main.js       상태 머신(편집·채점·판정) + UI 배선
    sdf.test.js   단위 테스트
```

`controls.js` 를 따로 뺀 이유는 `docs/PLAN.md` 의 리스크 표에 남겨 둔
"UI 배선을 별도 모듈로 빼는 것" 을 이 게임에서 먼저 적용했기 때문이다.
입력 해석과 상태 전이를 한 파일씩에 모으면 어느 쪽이 어긋났는지 찾기 쉽다.

`mesh.js` 는 three 를 쓰지 않습니다. `BufferGeometry` 조립은 `sculptView.js` 가
합니다. 순수 계산 모듈이라 Node 에서 그대로 테스트됩니다.

```js
// sdf.js
sdSphere(p, e) / sdBox / sdTorus / sdCapsule / sdRoundBox / sdEllipsoid
combine(a, b, op)              // union / intersect / subtract / smooth
shapeSdf(elements, p)          // 요소를 순서대로 쌓은 결과 SDF
smoothMin(a, b, k)
marchRay(origin, dir, sdf)     // → { hit, t }
silhouette(sdf, view)          // → { mask, depth }
silhouetteIou(sdfA, sdfB)       // 정면·옆 2시점 평균 IoU
```

**메시 추출**: 셀을 6개의 사면체로 분할해 부호 조합을 처리한다. 삼각형 방향은
"안쪽 영역에서 바깥쪽으로"를 기준으로 뒤집어 맞춘다. **와인딩이 뒤집히면 부호 체적이
음수가 되므로 1층 테스트 하나로 방향 오류를 잡는다.**

## 6. 검증 3층

### 1층 — 단위 테스트

| 묶음 | 검증 내용 |
|---|---|
| 기본형 SDF | 중심 0 · 표면에서 r · 축 밖 `\|p\|−r` · 박스 안/밖 · 토러스 관절 거리 |
| CSG | 합=`min` · 교=`max` · 차=`max(a,−b)` · 순서에 따라 결과가 달라짐 |
| 목표 어휘 | 라운드 박스 경계 · 엘립soid 근사 오차 · 매끈한 합이 컴볼루션보다 작음 |
| 메시 | 꼭짓점>0 · 인덱스 범위 유효 · **모든 간선이 정확히 2회(맨폴드)** · 법선 바깥 방향 · 메시 표면에서 SDF≈0 |
| 부피 | 부호 체적 > 0 · 48³ 메시 부피가 해석해와 5% 이내 · 24→32→48→64에서 오차 단조 감소 |
| 레이마칭 | 정면 방향 히트 거리≈r · 빗나가면 미히트 · 스텝 ≤ 0.9\|d\| · 결정론 |
| 실루엣 IoU | 동일 형태 1.0 · 분리된 형태 0 · IoU(A,B)=IoU(B,A) · 유사할수록 증가 |
| 레벨 | 8개 전부 기준 해법이 목표 IoU 이상 · 기준 해법이 부품 수 제한 이내 |

### 2층 — 기하 불변식 (0.5초마다)

SDF 값 전부 유한 · 메시 부피 > 0 · 부품 수 제한 이내 · 결과 메시 꼭짓점 > 0 ·
고스트 메시 존재 · NaN 없음

### 3층 — 화면 판정

4시점 캡처 · 콘솔 오류 0 · 자동 조작 `__gameApi.solve()` (기준 해법 자동 배치 → 채점 →
결과 팝업) · 모바일 390×844 HUD 겹침 0
