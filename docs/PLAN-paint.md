## 1. 왜 이 게임인가 — 기존 10종과 축 분리

| 게임 | 검증하는 능력 |
|---|---|
| `zoo/` | 절차적 지오메트리 조립 + 애니메이션 |
| `molecule/` | 클릭 상호작용 + 화학 규칙 + 판정 |
| `defense/` | 실시간 상태 머신 + 경로 + 전투 |
| `shapes/` | 3D 회전 + 격자 배치 + 형상 판정 |
| `ballistics/` | 수치 적분 + 연속 충돌 + 조준 |
| `robot/` | 역기구학 + 관절 체인 + 링크 충돌 |
| `maze/` | 1인칭 카메라 + 절차 생성 + 최단 경로 |
| `flock/` | 다체 에머전트 행동 + 이웃 탐색 |
| `sculpt/` | 암시적 곡면(SDF) + CSG + 등표면 메시 추출 |
| `gears/` | 회전 동역학 + 기어비 전파 + 톱니 위상 |

**이번에 새로 검증하는 능력**

1. **표면 셀 그래프** — 표면을 작은 정육면체(복셀)들의 집합으로 정의하고,
   6방향 인접 관계를 만든다. 앞의 게임들은 표면을 정점·함수·기어처럼 다른 방식으로 썼다.
2. **국소 flood fill** — 한 곳을 찍었을 때 **같은 색으로 연결된 영역만** 칠해진다.
   영역 경계를 넘지 않는다는 것을 수치로 검사한다.
3. **영역 분리 정확도** — 같은 색이 떨어진 두 곳에 있으면 **두 영역**이다.
   색 이름이 같아도 이어지지 않으면 한 번에 칠해지지 않는다.
4. **셀별 색 비교 채점** — 표면 복셀 중 목표 색과 일치하는 비율(%)로 점수를 낸다.
5. **최소 클릭 수(par)** — 목표를 완성하려면 최소 몇 번 칠해야 하는가.
   목표 색의 연결 영역 개수와 같다.

**판정이 "잘 보이면"이 아니라 숫자다.** 채점 값은 목표 복셀과 자기 복셀의 색 비교에서만 나온다.

## 2. 게임 정의

**핵심 루프**: 나무 인형(복셀 조립)을 골라 **목표 그림 색**으로 칠한다.
한 번 누르면 같은 색으로 이어진 영역 전체가 한꺼번에 칠해진다.

- **플레이어 조작**
  - 팔레트에서 색 고르기 → 인형 위를 클릭 → 그 칸과 같은 색으로 이어진 영역 전체가 칠해짐
  - 목표 그림은 말로 알려 준다(예: "머리 빨강 · 몸통 파랑 · 팔 초록")
  - **힌트 보기** 버튼 → 목표 색이 반투명으로 겹쳐 보인다(구경용)
- **판정**: 표면 복셀의 목표 색 일치율(%) + 사용한 칠하기 횟수
- **별점**: 별3 = 일치율 ≥ 99% 이고 클릭 ≤ par · 별2 = ≥ 90% · 별1 = > 0 · 별0 = 실패
- **레벨**: 8종. 같은 인형을 다른 색으로 칠하는 단계가 들어간다
- **추가 규칙**: 팔레트에 목표에 없는 색도 있다. 잘못 칠하면 일치율이 떨어진다

## 3. 수치 계약

| 값 | 값 | 단위 |
|---|---|---|
| 복셀 한 칸 | 0.08 | m |
| 표면 판정 | 노출된 면이 하나라도 있는 복셀 | — |
| 인접 | 6방향 (상하좌우앞뒤) | — |
| 일치율 허용 오차 | 1 % | — |
| 파레트 색 수 | 4 ~ 5 | 종 |
| 목표 영역 수(par) | 목표 색의 연결 영역 개수 | 개 |

### 칠하기 규칙

```
floodFill(start):
  같은 색인 복셀만 BFS 로 펼친다
  그 영역 전체를 새 색으로 바꾼다
```

- 경계를 넘어가지 않는다 → 옆 영역은 그대로 남는다
- 같은 색이 떨어져 있으면 두 번 칠해야 한다

| # | 레벨 | 인형 | 조각 수 | 목표 색 수 | par |
|---|---|---|---|---|---|
| 01 | 로봇 얼굴 | robot | 머리·눈·입 | 3 | 확정 |
| 02 | 로봇 전체 | robot | 9조각 | 4 | 확정 |

| 05 | 자동차 | car | 6조각 | 4 | 확정 |
| 06 | 우주선 | rocket | 6조각 | 4 | 확정 |
| 07 | 고양이 | cat | 7조각 | 5 | 확정 |
| 08 | 최종 완성 | robot + rocket | 15조각 | 5 | 확정 |

**레벨은 코드로 고정한다.** 각 레벨에 대해
1. 목표 색으로 칠하면 일치율 100% 가 되고,
2. **최소 클릭 수 == par** 이며,
3. 같은 색이 떨어져 있으면 두 영역으로 세어지는지
단위 테스트가 확인한다.

## 6. 검증 3층

### 1층 — 단위 테스트

| 묶음 | 검증 내용 |
|---|---|
| 복셀 집합 | 상자가 겹치지 않으면 겹치는 복셀이 없다 · 표면 복셀 판정 |
| 인접 그래프 | 6방향 이웃만 연결 · 대칭 · 차수 합이 6N 이하 |
| flood fill | 같은 색 영역만 칠해진다 · 다른 색 영역은 남는다 · 경계가 넘어가지 않는다 |
| 영역 분리 | 떨어진 같은 색은 두 영역 · 붙어 있으면 한 영역 |
| 일치율 | 전부 맞으면 1 · 하나 틀리면 (N-1)/N · 표면만 센다 |
| par | 목표 색칠의 최소 클릭 수 == par |

### 2층 — 기하 불변식 (0.5초마다)

모든 복셀 색 유한 · 복셀 수 == 표 정의 · 겹치는 조각 0 · 인접 그래프 차수 일관 ·
일치율 0~1 범위

### 3층 — 화면 판정

4시점 캡처 · 콘솔 오류 0 · 자동 조작 `__gameApi.solve()` (목표 색으로 칠하기 → 결과 팝업) ·
모바일 390×844 HUD 겹침 0

## 9. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 인스턴스 색 갱신이 느리다 | InstancedMesh + instanceColor 로 복셀 수와 무관하게 한 번에 갱신 |
| 클릭이 빗나간다 | 인스턴스 레이캐스트의 `instanceId` 를 그대로 복셀 키로 쓴다 |
| flood fill 이 경계를 넘는다 | 1층 테스트에서 다른 색 영역이 남는지 검사 |
| 같은 색이 이어져 있어 par 이 틀어진다 | par 은 목표 색의 연결 영역 개수로 계산하고 테스트로 고정 |
| 채점이 카메라에 따라 달라진다 | 채점은 복셀 색 비교뿐이라 화면과 무관하다 |
| 복셀 수가 많아 모바일이 느리다 | 표면 복셀만 인스턴스로 그린다(내부는 생략) |
