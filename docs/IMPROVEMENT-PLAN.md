# 개선 계획 — 18종 게임의 신뢰성·확장성·접근성

- 작성일: 2026-10-25
- 대상: `m31-flash-3d-bench` 전체
- 원칙: 게임별 검증 3층(단위 · 불변식 · 화면)을 유지하고, 새 검사가 실제 실패를 잡는지 먼저 확인한다.

## 1. 진단 요약

- 강점: 게임 18종, 단위 테스트 615개, 4시점 화면 판정, CI, `vendor/`·폰트 자체 호스팅, `docs/checks.json` 동기화.
- 약점: 게임 추가 속도에 비해 UI 통합·문서 진실성·모바일/접근성 검증이 뒤처졌다.
- 핵심 방향: 게임 수를 늘리기 전에 **공통 실행 계층과 검사 계층을 먼저 정리**한다.

## 5. 실행 순서

1. P0 전체 + 방어 검사(팝업 스타일, 백링크, 엔딩, 모바일 터치).
2. P1-1 → P1-7 → P1-2 → P1-3 → P1-4 → P1-5 → P1-6.
3. P2-1 → P2-2 → P2-3 → P2-4.
4. `npm test`, `npm run qa`, `npm run qa:visual`, `npm run qa:sync`, `npm run qa:ui` 통과 후 README 내역 기록.

## 6. 검증 원칙

- 새 검사는 **일부러 깨뜨려 실패하는지** 확인한 뒤 통과시킨다.
- 화면 변경은 4시점·모바일·팝업 상태를 모두 캡처한다.
- 문서 수치는 `docs/checks.json`과 대조하고, 산문에 박은 게임 수는 가능하면 피한다.
- 게임 폴더를 옮겨도 실행된다는 주장은 `common/` 동반 이동 조건을 명시한다.
