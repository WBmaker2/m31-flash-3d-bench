# M3.1 FLASH / 3D BENCH

MiniMax M3.1 Flash(`minimax-m3.1-flash-free`)가 three.js 3D 구현을 어디까지 해낼 수 있는지 확인하는 실험입니다.
외부 API 호출 없이 모델이 코드를 직접 작성했고, 숫자는 단위 테스트가, 화면은 4시점 자동 판정이 확인합니다.

각 게임은 서로 완전히 분리되어 있습니다. 폴더를 통째로 다른 곳으로 옮겨도 그대로 실행됩니다.

| 폴더 | 게임 | 검증하는 능력 | 판정 |
|---|---|---|---|
| [`zoo/`](zoo/) | 폴리곤 동물원 | 절차적 지오메트리 조립 + 애니메이션 | 도감 8항목 · 찾기 게임 3단계 |
| [`molecule/`](molecule/) | 3D 분자 빌더 | 클릭 상호작용 + 화학 규칙 + 판정 | 분자 9종 · 레벨 2단계 · 점수 |
| [`defense/`](defense/) | 3D 타워 디펜스 | 실시간 상태 머신 + 경로 + 전투 | 난이도 3단계 · 웨이브 10개 · 별점 |
| [`shapes/`](shapes/) | 3D 도형 조립실 | 3D 회전 + 격자 배치 + 형상 판정 | 레벨 12단계 · 칸 단위 판정 |
| [`ballistics/`](ballistics/) | 3D 탄도 타워 | 수치 적분 + 연속 충돌 + 조준 | 레벨 8종 · 예측 궤적 == 실제 궤적 |
| [`robot/`](robot/) | 3D 로봇 팔 조립실 | 역기구학 + 관절 체인 + 링크 충돌 | 레벨 8종 · IK 왕복 오차 1e-9 |

공통 부분(저장·진행·결과 화면)은 [`common/`](common/) 에 있고, 게임 규칙은 각 폴더에
남습니다.

각 게임 폴더에는 그 게임만 필요한 파일만 들어 있습니다. 공유 런타임 의존성은 없습니다.

## 공개 주소 (배포)

https://wbmaker2.github.io/m31-flash-3d-bench/

랜딩에서 카드의 **PLAY** 버튼을 누르면 그 자리에서 바로 플레이됩니다.

## 로컬 확인

빌드 단계가 없습니다. `three@0.186.1`을 CDN에서 importmap으로 불러옵니다.

```bash
python3 -m http.server 5174
# 브라우저에서 http://localhost:5174/  →  랜딩에서 게임 선택
```

ES 모듈이라 `file://`로 직접 열면 안 됩니다. 임의의 정적 서버면 됩니다.
`zoo/` `molecule/` `defense/` `shapes/` `ballistics/` `robot/` 폴더에 바로 들어가서 개별로 실행해도 됩니다.


## 랜딩 페이지

`index.html`이 이 저장소의 진입점입니다. 5개 게임을 카드로 소개하고, 카드의
**PLAY** 버튼을 누르면 같은 자리에서 바로 플레이합니다(모달 iframe). 마우스를 카드에 올리면
그 게임의 다른 각도가 차례로 보입니다.

랜딩에 적힌 검사 수치는 하드코딩이 아니라 `docs/checks.json`과 대조됩니다. 실제 실행 결과와
어긋나면 랜딩 검사가 실패하므로, **홍보 페이지가 거짓말하지 못하게** 되어 있습니다.

```bash
npm run qa:cards                               # 카드 이미지 + checks.json 재생성
npm run qa                                     # 랜딩 검사 (링크·모달·수치 대조)
```

## 검사 하네스

`scripts/shot.mjs`는 각 게임을 헤드리스 브라우저로 띄워 **콘솔 오류를 수집하고 스크린샷을 남기며, 화면을 스스로 판정합니다.**

```bash
npm install
npm run qa             # 게임 6종 + 랜딩 전체 검사
node scripts/shot.mjs zoo
node scripts/shot.mjs molecule
node scripts/shot.mjs defense
node scripts/shot.mjs ballistics
node scripts/shot.mjs robot
node scripts/shot.mjs landing
```

- 게임별 대표 조작(종 교체 · 분자 배치 · 타워 설치 → 웨이브 진행)을 자동 수행합니다.
- **4개 시점**(기본·정면·측면·위)에서 각각 캡처합니다. 한 각도에서만 보이는 요소는 다른 각도에서 드러납니다.
- 자동 판정 항목
  - 콘솔 오류 · 페이지 예외 · 요청 실패
  - **기하 불변식 위반** (아래 2층)
  - 어떤 개체도 화면에 보이지 않음
  - 시점을 바꿔도 화면이 1% 미만으로만 변함 (장면이 비었거나 평평함)
- 실패하면 사유를 출력하고 종료 코드 1입니다.

`landing` 타깃은 랜딩 전용으로, 카드 링크 5개 응답 확인 → PLAY 클릭 → 모달 안에서 게임이
실제로 준비되는지 확인 → **랜딩 표시 수치와 `docs/checks.json` 대조** → 모바일 화면 캡처를 합니다.

## 검증 3층

3D는 **값이 맞는 것과 화면에 보이는 것이 다릅니다.** 2D는 픽셀 좌표가 곧 결과지만, 3D는 카메라·조명·가림이 결과를 좌우합니다. 그래서 1층만으로는 부족했습니다.

| 층 | 도구 | 잡는 것 | 실행 |
|---|---|---|---|
| 1층 순수 계산 | vitest, 브라우저 불필요 | 단위 혼용, 수식 오류 | `npm test` |
| 2층 기하 불변식 | `*/src/invariants.js` | 겹침, 파묻힘, 안 읽힘 | `?debug=1` 또는 상시(배지로 표시) |
| 3층 화면 판정 | `scripts/shot.mjs` | 안 보이는 것, 빈 장면 | `node scripts/shot.mjs <게임>` |

1층 테스트는 게임 폴더 안에 있습니다(`*/src/*.test.js`). 부모 저장소의 vitest가 자동으로 수집하므로 `npm test` 한 번이면 전부 돕니다. `three`는 브라우저(CDN)와 Node(테스트) 양쪽에서 **같은 버전 0.186.1**을 씁니다.
단위 테스트는 **220개**입니다(게임 203 + 공통 17).

## 코딩 규칙 (3D에서 반복해서 겪은 실패에서 온 것)

1. **단위는 이름에 명시합니다.** 수학 함수는 라디안만 반환하고 `*Deg`/`*Rad` 접미사로 구분합니다. 표시 변환은 화면에 쓰는 한 곳에서만 합니다.
2. **분기는 변화량만, 상태는 무조건 갱신합니다.**
   ```js
   if (moving) angle += speed * delta;   // 변화량만 조건부
   position.copy(orbitPosition(angle));  // 파생 상태는 항상 계산
   ```
3. **부착은 표면 기준입니다.** 절대 오프셋 대신 "몸체 반지름 + 돌출"로 계산합니다(`zoo/src/attach.js`).
4. **좌표 변환은 도메인 경계에서 한 번만.** 셀↔월드는 `defense/src/grid.js`의 두 함수만 씁니다.
5. **파라미터는 단일 진실 공급원.** 종·원자·타워·적 스펙은 각 게임의 데이터 파일 한 곳에 모읍니다.

## 모델에 3D를 맡길 때의 지침

1. **기하를 수치로 명시하세요.** "팔찌 만들어줘"보다 "둘레 12, 두께 0.1"이 정확합니다.
2. **표면 관계를 말하세요.** "귀는 머리 표면에서 0.05만큼 나와야 보인다"처럼 상대 배치를 지정해야 파묻히지 않습니다.
3. **단위를 말하세요.** deg인지 rad인지 안 쓰면 섞입니다.
4. **판정 기준을 함께 주세요.** "결합각 104.5° ± 1°"처럼 수치로 제시하면 검증할 수 있습니다.
5. **스크린샷 루프를 기본값으로 두세요.** 구현 → 4시점 캡처 → 이미지를 모델에 첨부 → 수정.
6. **순수 로직은 브라우저 밖에서 먼저 검증하세요.** 유닛 테스트가 있는 함수는 모델이 다시 써도 수치로 확인할 수 있습니다.

## 모델 성능에서 읽은 것

### 잘한 것
- **절차적 지오메트리 조립.** 구·원기둥·원뿔·십면체만으로 파라미터 표를 보고 4종 동물을 만들고, 호흡·보행·꼬리 흔들림을 붙였다. 별도 지오메트리 자산 없이 저폴리 룩이 나왔다.
- **상태를 세 객체로 나누는 구조.** `stage`(렌더러/조명/카메라) · `species`/`elements`(데이터) · `animals`/`chemistry`(도메인) 로 파일을 갈라 두니 한 파일이 250줄을 넘지 않았다.
- **HUD와 상태 표시.** 게임 규칙 설명을 한국어로 상태 패널에 노출하는 부분을 스스로 설계했다.

### 놓친 것 (스크린샷을 보지 않으면 못 찾을 것들)
1. **정지 상태에서 모든 개체가 원점에 겹쳤다.** 궤도 좌표를 "움직일 때만" 갱신하고 있어서, 걷지 않으면 위치 갱신이 아예 일어나지 않았다. 상태 계산과 렌더링이 엮인 자리의 전제 조건.
2. **판다의 눈·귀·무릎이 머리 안쪽에 파묻혀 있었다.** 패치의 반지름이 머리 반지름보다 작아 완전히 내부에 들어갔고, 화면에서는 "하얀 덩어리"로 보였다. 3D에서 가려진 부분을 놓치기 쉽다는 전형적인 사례.
3. **결합각 계산에서 도(°)와 라디안을 섞어 비교했다.** `measureAngle`는 라디안을, 목표 결합각은 도로 반환해 비교했고, 결과적으로 결합각이 180°로 펴졌다. 상태 메시지에는 "104.5°"가 정상으로 찍혀 있어 **숫자가 맞아 보여도 계산은 틀릴 수 있다**는 사례.
4. **분자가 카메라를 향한 평면이 아니라 측면으로 누워 있었다.** 결합각은 맞는데 도형이 안 읽혔다. 3D 구조는 "값이 맞다"와 "보인다"가 다르다.

### 그 뒤에 붙인 검증

위 4건은 전부 **텍스트로는 잡히지 않았고, 스크린샷을 직접 봐야만 보였습니다.** 그래서 같은 실패를 두 번 하지 않으려고 검증 3층을 붙였습니다.

- 1번 → 유닛 테스트(정지 상태에서도 좌표가 반영됨) + 불변식(개체 간 거리)
- 2번 → 유닛 테스트(패치 돌출량) + 불변식(표면 밖 여부)
- 3번 → 유닛 테스트(결합각 ±0.5°) + 단위 계약 테스트
- 4번 → 유닛 테스트(분자 축 ↔ 시선 각도) + 불변식(기본 시점에서만 판정)

이 검증을 붙인 뒤에는 **새로운 실제 버그 2건이 더 나왔습니다.**

- `validate`가 이웃 원자를 다중집합으로 비교하지 않아, 중심이 다른 분자를 정답으로 받아들였습니다. 유닛 테스트가 잡았습니다.
- 경로 지점이 웨이포인트마다 중복 삽입돼 길이가 어긋났습니다. 유닛 테스트가 잡았습니다.

### 다섯 번째 게임(탄도 타워)에서 다시 확인한 것

물리 수치는 "그럴듯해 보이면" 깨집니다. 이번에는 두 가지가 실제로 드러났습니다.

1. **접촉 판정이 부동소수점에서 흔들렸습니다.** 구가 상자 위면에 정확히 닿는 경우
   `dx² + dy² + dz² <= r²` 이 오차 때문에 거짓이 될 수 있었습니다. 경계도 충돌로
   보는 명시적 여유(1e-9)를 넣고, 그 경계 자체를 유닛 테스트로 고정했습니다.
2. **유한차분 적분은 "사거리 v²/g" 를 만족하지 못합니다.** 위치 증가분을 대충
   더하는 방식은 오차가 쌓여 최대 사거리가 1% 넘게 어긋납니다. 이 게임은 스텝 안의
   가속도를 상수로 보고 `p' = p + v·dt + ½a·dt²` 로 정확히 갱신해, 중력만 있을 때
   해석해와 오차 1e-9 안에서 같아지고 에너지 `v²/2 + g·y` 도 보존되게 했습니다.

또 하나는 설계로 막은 문제입니다. **예측 궤적과 실제 궤적은 같은 함수
(`simulateFlight`)를 호출합니다.** 미리보기를 따로 만들면 두 값이 언제든 어긋납니다.

### 결론
- 지오메트리 생성과 애니메이션은 이 모델의 강점 영역이다. 스프라이트 없이도 통용 3D 물체를 만든다.
- 반면 **좌표·배치·단위 같은 "공간과 수의 관계"는 직접 검증하지 않으면 조용히 틀린다.** 스크린샷을 찍어 눈으로 확인하는 루프가 반드시 붙어야 한다.
- 상태가 여러 조건에 얽힌 부분(타워 디펜스 웨이브 관리, 분자 판정)은 한 파일에 전이 규칙을 모아 두는 편이 안전했다.
- 더 나아가, **"화면에 보이는가"도 "값이 맞는가"와 별개의 판정 기준**으로 다뤄야 한다. 불변식과 4뷰 캡처는 이 둘을 분리해서 검사한다.
- **같은 값을 두 경로에서 쓰는 구조는 테스트로도 못 잡는 어긋남을 원천적으로 막는다.** 탄도 타워의 예측 궤적과 실제 궤적이 같은 함수에서 나오듯이 말이다.

## 공통 기술 결정

- `three@0.186.1` 고정. **저장소 안 `vendor/` 에서 먼저 불러오고, 없으면 CDN으로 되돌아갑니다.**
  (`index.html` 이 importmap을 동적으로 만들어 로컬 우선 → CDN 폴백을 구성합니다.)
  학교망처럼 CDN이 막힌 환경에서도 게임이 뜨고, 로컬에서 실행할 때는 네트워크가 필요 없습니다.
- `vendor/` 는 `npm run vendor` 로 `node_modules/three` 에서 다시 복사할 수 있습니다.
- `THREE.Clock` → `THREE.Timer` (three r186 에서 Clock 은 폐기 예정), `PCFSoftShadowMap` → `PCFShadowMap` (r186 에서 삭제되어 조용히 대체되고 있었습니다).
- `THREE.OrbitControls` 전역 접근 금지(라이브러리에서 제거됨) → `three/addons/controls/OrbitControls.js` import.
- 포인터 좌표는 `canvas.getBoundingClientRect()` 기준. `window.innerWidth`를 쓰면 캔버스 오프셋에서 어긋난다.
- `renderer.setSize(w, h, false)` — CSS 크기는 CSS가, 버퍼 크기는 JS가 담당.
- 게임 루프는 `setAnimationLoop` + `dt = Math.min(clock.getDelta(), 0.1)` + 1/60 고정 스텝 누적. 탭 전환으로 `dt`가 튀는 사고를 막는다.
- 물리엔진 미사용. 충돌·사거리·이동은 전부 직접 계산한다.
